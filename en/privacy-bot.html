02

What Data the Bot Collects and What It Never Collects

The Bot collects only the minimum technical data supplied by the Discord API during a direct user interaction.

Data Category Examples / Format Data Source Sensitivity Level
Public Discord Identifiers (Snowflakes) user_id (requesting user ID), guild_id (server ID), channel_id (channel ID). Generated and transmitted by the official Discord Gateway API. Public / Platform technical ID.
Command Parameters & Prompts Text submitted in slash command arguments (e.g. /query, /summary), button clicks, or dropdown selections. Voluntarily provided by the user when invoking a command. Non-confidential / Prompt input.
Operational Technical Metadata Request timestamp, execution status code (success/error), rate-limiting counters for spam prevention. Automatically generated by the Bot runtime server. Operational telemetry.
Server-Specific Settings (Optional) Designated bot response channel, preferred language, or authorized role configuration. Configured by server administrators. Functional configuration.
🚫
Data We NEVER Collect or Store:
  • Passwords or Personal Tokens: We never ask for Discord credentials, personal passwords, or authentication tokens.
  • Financial Data: We do not process credit/debit card numbers, bank accounts, or billing addresses.
  • Passive Channel Eavesdropping: The Bot DOES NOT read, scan, or store messages in channels where it is not explicitly invoked via a command or mention (full Message Content Intent compliance).
  • Voice Channels: The Bot does not listen to, intercept, or record audio/video streams in Discord voice channels.
  • Sensitive Personal Data: We do not collect racial/ethnic origin, religious beliefs, political opinions, health records, or biometric identifiers.
03

Purposes of Data Processing

Data processed by the Bot is strictly limited to the following legitimate technical purposes:

  1. Delivering Requested AI Services: Processing user prompts, text, and command options to generate responses, summaries, calculations, or automations in real time.
  2. Response Routing: Using channel_id and user_id to deliver outputs back to the proper channel and user.
  3. Security, Stability & Abuse Prevention: Enforcing rate limits to prevent DoS/DDoS attacks, spam floods, and infrastructure degradation.
  4. Server Preferences Persistence: Remembering administrator-configured settings (such as response channels) across bot restarts.
💡
Strict No-Sale Guarantee: RACM NEVER SELLS, LEASES, TRADES, OR MONETIZES user or server data to advertisers, ad networks, marketing agencies, or data brokers under any circumstances.
04

AI Model Processing & Third-Party Infrastructure

To provide Natural Language Processing (NLP), code generation, and automated analytics, the Bot may forward user-submitted command text to AI inference providers (such as Google Gemini API, OpenAI API, Anthropic API, Groq, or private self-hosted inference servers).

We guarantee that:

  • Encrypted Transmission: All traffic between the Bot and AI inference endpoints is encrypted in transit over HTTPS / TLS 1.3.
  • Developer API Agreements (No Public Training): Enterprise API endpoints used by RACM operate under developer terms specifying that inference inputs are NOT used to train or improve public foundation models without explicit opt-in.
  • Identity Dissociation: AI providers receive only the prompt text necessary to produce the answer, decoupled from civil personal identities.
05

Data Retention & Automatic Purge Policies

RACM enforces strict expiration and minimal retention windows based on data type:

  • In-Memory Execution Data (RAM / Ephemeral Cache): Command arguments and short-term conversation context stay in volatile memory only for the seconds or minutes required to fulfill the request and maintain active session continuity, after which they are automatically discarded.
  • Technical Debugging & Error Logs: When a software exception occurs, technical error logs (error codes and timestamps) may be retained for a maximum of 14 to 30 calendar days strictly to diagnose bugs and maintain uptime before scheduled purging.
  • Server Preferences & Security Blacklists: Server configurations are kept only while the Bot remains authorized on that server. IDs blacklisted for severe abuse are retained solely to protect service integrity.
06

Technical & Organizational Security Measures

We apply industry-standard safeguards to protect processed data against unauthorized access, loss, or tampering:

  1. End-to-End Transport Encryption: All links between the Bot, Discord Gateway, and external microservices use encrypted TLS / Secure WebSockets (WSS).
  2. Secret & Credential Management: Bot tokens, API keys, and sensitive environment variables are stored in restricted vaults, never exposed publicly, and rotated periodically.
  3. Principle of Least Privilege: The Bot requests only the Discord permissions strictly required to run slash commands and post responses (Use Slash Commands, Send Messages, Embed Links).
07

User Rights: Access, Rectification, Erasure & Objection (GDPR / ARCO)

In accordance with international privacy standards (GDPR) and Mexican data protection law (LFPDPPP), every Discord user and server administrator holds the following rights:

  • Right of Access: Request confirmation of any data linked to your Discord ID stored by the Bot.
  • Right to Rectification: Request correction of inaccurate server settings.
  • Right to Erasure (Right to be Forgotten): Request permanent deletion of any identifier, server preference, or residual record stored in our systems.
  • Right to Object: Opt out of processing at any time by stopping interaction or removing the Bot from your server.
📨
How to Request Data Deletion: To exercise any of your rights or request a full purge of records linked to your user or server ID, simply message us on our Official WhatsApp (+52 56 6490 3696) or submit our web contact form including your Discord Snowflake ID. Deletion requests are fulfilled within 48 to 72 business hours.
08

Children's Privacy

This Bot is not directed to individuals under 13 years of age (or the minimum digital consent age in the user's jurisdiction). In compliance with Discord's Terms of Service and COPPA, we do not knowingly collect data from children under 13.

If a parent, legal guardian, or server administrator believes a child under 13 has interacted with the Bot and left stored records, please contact us immediately so we can promptly delete them.

09

By using the Bot, the User acknowledges these necessary operational transfers required to deliver the service.
